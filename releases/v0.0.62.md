# pain001-loader-mt101 v0.0.62

Benchmark and tooling release. No change to the parser and no API
change; the public surface is still a single function.

The version moves because every member of the `pain001` suite ships the
same number.

## What's new

**The block-4 wire format is benchmarked.** A bare field list is the
convenient shape for a fixture, but banks send it wrapped in
`{1:...}{2:...}{4: ... -}` — and that wrapper is the only thing that
exercises `_unwrap_block4`. Nothing measured that path before. It costs
1.10x a bare list, with a guard against unwrapping doing work
proportional to the message more than once.

**Field-dense transactions are benchmarked.** `_lookup` searches tag by
tag, so the risk is that it becomes quadratic in the number of fields
present — invisible on the uniform fixtures the unit tests and the
existing benchmark use. A transaction carrying every optional field
costs 1.10x a minimal one.

Both ceilings are set at 3x against a measured 1.10x: loose enough not
to flake on a shared runner, tight enough that anything algorithmic
trips them.

**`ruff format --check` now runs in CI.** `pain001-loader-xlsx` already
enforced it and this repo did not, so four files had drifted out of
format with nothing configured to notice.

## Compatibility

No API change:

```python
from pain001_loader_mt101 import parse_mt101

rows = parse_mt101(swift_message_text)
```

`pain001 >= 0.0.55, < 1` unchanged.
